# Постоянная привязка ответов к поручениям: кандидат

30 октября 2026 года. **Проверен локально, не установлен.** Рабочий проект Google сохраняет ранее установленные исправления доступа, кнопок, файлов, очереди и восстановления ответа. Новых операций в Google для этого кандидата не выполнялось.

Рецепт: `tools/clasp/legacy-task-binding.cjs`. Изменения для проверки: `patches/legacy-task-binding.patch`. Исходные версии и кандидат 2.0.5 сохранены. Маршрут записи Google этот патч пока не принимает; файл запроса запуска не менялся.

## Проблема

Кнопка и сохранённый выбор используют номер строки. После сортировки ответ попадает в другое поручение. Кроме того, повтор сообщения после сбоя может использовать более поздний выбор студента. Первые три теста воспроизвели эти ошибки до исправления.

Во время проверки воспроизведены ещё три опасных сценария: сортировка во время загрузки файла, сортировка после добавления ответа и отказ сохранения нового выбора, после которого остаётся старый выбор.

## Что меняется

Кнопки передают постоянный ID поручения, а сохранённый выбор содержит JSON с версией, ID чата и ID поручения. Старые кнопки с номером строки и старые значения выбора не преобразуются наугад: студент получает просьбу открыть `/tasks`, выбрать поручение и отправить ответ новым сообщением. Недоступная кнопка также отменяет прежний выбор, чтобы ответ не ушёл в ранее выбранное поручение.

Проверяются личный чат, совпадение отправителя с чатом, разрешённый доступ, активный статус и единственность пары «чат + ID». Пустой ID, управляющие символы, пробелы по краям, дубликаты и превышение лимита Telegram в 64 байта требуют проверки. Учитываются байты UTF-8, а не количество символов. Числовой ID допускается как явный ID; он не считается номером строки. Одинаковые ID у разных студентов не дают доступа к чужому поручению.

До загрузки файла фиксируется привязка конкретного сообщения: `BOUND`, `UNLINKED` или `RESELECT`. Снимок содержит только версию, чат, номер сообщения, признак владельца, решение и ID поручения — без текста ответа, Telegram file ID и ссылки Drive. Повтор использует этот снимок. Более поздний выбор не перепривязывает старое сообщение. Сохраняются автоматический выбор единственного активного поручения, личные входящие владельца, обычная доработка и существующие форматы ответов.

Для снимков используется уже имеющаяся в кандидате 2.0.5 функция `operationSnapshot_`, а не новый общий механизм. Первичная фиксация в штатной очереди разрешена только на первой попытке `PROCESSING`, без записанной ошибки и с подтверждённым последним предшествующим выбором в этом чате. Если первую привязку сохранить не удалось, повтор не подставляет новый выбор. Операторский повтор `DEAD` без снимка или существующего ответа останавливается до сброса счётчика.

После загрузки файла и после добавления ответа строка поручения повторно ищется по ID. Закрытое, удалённое или неоднозначное поручение не заменяется другим. Очистка выбора в обычной обработке и при восстановлении ответа затрагивает только совпадающий типизированный выбор; более новый выбор другого поручения сохраняется.

## Дополнительный технический лист

После отдельного разрешения используется или создаётся **«Снимки операций»** в существующей книге бота. Колонки: **«Ключ», «Payload JSON», «Создано»**. Это схема из кандидата 2.0.5. Несовместимый лист не перезаписывается; существующие строки и дополнительные колонки сохраняются. Лист наследует права книги и содержит приватные идентификаторы, поэтому его содержимое нельзя публиковать в репозитории, чате или журнале Actions.

Изменяются шесть существующих функций: `taskKeyboard_`, `chooseTask_`, `processMessage_`, `processCallback_`, `recoverLegacyReply_`, `replayDeadUpdate_`. Добавляются восемь узких вспомогательных функций. Бизнес-листы, девять полей ответа, одиннадцать полей поручения, настройки ресурсов и манифест не меняются.

## Проверки

Добавлены **24 регрессионных теста** в `tests/legacy-task-binding.cjs` и общий запуск `tools/check-local.sh`. Проверены старые кнопки и выборы, сортировка на разных этапах, повтор после сбоя, отсутствие и неоднозначность ID, UTF-8 и числовые ID, авторизация callback, истёкший ACK, сбой снимка до и после записи, повреждённые снимки, изменение роли, закрытие поручения, отказ сохранения callback, новый подтверждённый выбор после отказа, доработка, личные входящие и очистка выбора при восстановлении ответа.

Полный `bash tools/check-local.sh`: **596 Python + 282 Node теста прошли**, 6 демонстраций на искусственных данных. Рецепт применён только в памяти к последнему проверенному исходнику Google: меняется один основной файл, остальные семь сохраняются; 65 глобальных функций без коллизий, общий синтаксис корректен. Реальные Telegram, Drive и Google Sheets для нового патча не тестировались.

|---|---|---|---|---|

## Ограничения и установка

Рабочая точка входа — существующий опрос с долговременной очередью под `ScriptLock`. Прямой вызов обработчика вне очереди не является поддерживаемым способом доказать историю выбора; тестовые вызовы не создают новый публичный API.

Постоянные ID нельзя менять или переиспользовать после выдачи поручения и записи ответов. Генератор ID в `sendPendingTasks` этим патчем не заменяется. Коллизии обнаруживаются, но не исправляются автоматически. Удаление строки и создание другого поручения с тем же ID нельзя надёжно различить без отдельного реестра идентичности.

Повторный поиск сокращает риск сортировки во время обработки, но ручная правка между последним чтением и записью всё ещё не участвует в общей транзакции. Во время приёмки не следует одновременно сортировать или редактировать данные.

Очередь и снимки не удаляются по времени: иначе повтор потеряет доказательство привязки. Нужны контроль роста и согласованная архивация. Старое отклонённое сообщение сохраняется в исходном payload очереди; студенту предлагается отправить новое сообщение после выбора. Доставка уведомлений, защита от формул Sheets и атомарность ручных правок остаются отдельными задачами.

Перед установкой нужны разрешение на этот патч и технический лист, отдельный защищённый маршрут записи, свежая сверка полного проекта, зашифрованная резервная копия, подтверждение GitHub и повторное чтение результата. Рабочий опрос, триггеры, рассылки и новый deployment для демонстрации не запускаются. Пока эти действия не выполнены, нельзя объявлять кандидат установленным или лист созданным.
