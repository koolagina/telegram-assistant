# Повторное создание личной задачи через /add

30.10.2026. **Локальный кандидат, не установлен.** Пока владелец без компьютера, реальных операций или новых подтверждений не требуется.

| Дефект | Причина | Исправление | Тест | Результат | Остаточный риск |
|---|---|---|---|---|---|
| Повтор одного /add создаёт ещё одну задачу | На каждой попытке ID строится из времени и случайного числа | Передача исходного message_id, постоянный L-TG-chat-message, ScriptLock и appendOnce_ | Повтор одного сообщения | PASS | Ручные дубли требуют сверки |
| Принятая запись с исключением создаёт дубль на повторе | Обработчик не ищет результат прежней попытки | Поиск по постоянному ID до append | append accepted → exception → retry | PASS | Если строку вручную удалить, доказательство создания исчезает |
| Ошибка подтверждения в Telegram размножает задачи | Queue повторяет весь ownerAdd_ после отправки | Повтор использует сохранённую задачу | send failure → retries → DEAD | PASS | Подтверждающие сообщения команды всё ещё могут повторяться; это не exactly-once уведомления |

## Реализация

`tools/clasp/legacy-owner-add.cjs`: узкий перенос идеи постоянного Telegram-ID из ownerAdd_ кандидата 2.0.5. Меняются только передача message_id в processMessage_ и функция ownerAdd_. Не переносится общий реестр задач, не меняются статусы, не добавляются листы или поля.

Создание защищено существующими withScriptLock_ и appendOnce_. Дополнительно проверяются права владельца, корректность исходных идентификаторов, уникальность найденного ID и совпадение текста. Нет fallback на случайный ключ при отсутствии message_id. Конфликт с вручную изменённым текстом требует сверки. Повтор не переписывает дату, статус и прочие поля уже существующей задачи. Начальные знаки равенства и апострофы сохраняют установленную защиту legacySheetLiteral_. Разные Telegram-сообщения с одинаковым текстом создают разные задачи намеренно.

Старые ID сохраняются. Существующие /plan и /done принимают новые ID; /done отдельно проверен тестом. Прямые вызовы ownerAdd_ без message_id для непустого текста теперь отклоняются, автоматическая миграция таких вызовов не выполняется. Рабочая схема из восьми колонок сохранена.

## Проверки и ограничения

Три исходных теста сначала воспроизвели дубли на реальном legacy-алгоритме с моками Telegram, затем прошли с исправлением. Всего **15 тестов**: повторы, частичный append, сбой подтверждения, разные сообщения, старые строки, дата/статус, конфликты/дубликаты, формулы/апострофы, неверные ID, права/lock, пустая команда, queue DEAD и /done.

Полный `bash tools/check-local.sh`: **596 Python +374 Node успешно**, 6 offline демонстраций. На последнем независимо подтверждённом Google-source рецепт применён только в памяти: один изменённый main, семь файлов сохранены, 71 глобальная функция без коллизий, общий синтаксис PASS. Публичный diff: `patches/legacy-owner-add.patch`.

Реальная обработка /add не проверялась. Новый live review/apply маршрут не добавлен; Google исходники не менялись. Текущее право runtime-доступа после отзыва неопознанного OAuth-приложения остаётся неизвестным. Подтверждающие сообщения /add не включены в технический outbox ответов и могут повторяться при сбое. Уже созданные дубли не удаляются. ScriptLock не блокирует ручное изменение листа.

Перед будущей установкой требуется отдельное разрешение конкретного патча, свежая сверка, зашифрованная копия и независимое повторное чтение. Пока владелец без компьютера, эту установку не запускать и не требовать участия.
