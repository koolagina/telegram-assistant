| Условие | Что известно сейчас | Что должно стать проверяемым свидетельством |
|---|---|---|

1. Зафиксировать свежий source, runtime-авторизацию и владельца polling, сохранив рабочие функции. Не запускать опрос или setup ради проверки.

3. На заранее выбранном runtime собрать компоненты и выполнить `inspect_academic_runtime` на согласованных приватных локальных хранилищах. Этот запуск сам по себе не даёт права на live.
4. Отдельно согласовать ограниченного получателя и отправку; непосредственно перед ней заново готовить ответ. После API acceptance проверить результат по разрешённому каналу, не называть его доставкой без свидетельства.
5. Проверить повтор и восстановление после сбоя в ограниченном сценарии, затем решить о расширении. До этого не менять общий poller, триггеры, журнал, календарь или deployment.
