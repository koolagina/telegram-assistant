# «Что требует моего решения» — локальный кандидат

Команда `/decisions` собирает единую приватную очередь владельца: заявки на консультации, работы, требующие проверки преподавателя, и технические исходы отправок, требующие сверки. Это read-only представление актуальных источников, без новой копии задач и без изменений оценок/заявок/отправок.

## Как выглядит

- Счётчики трёх категорий, фильтры, до пяти пунктов на страницу.
- Сначала просроченное, затем сроки сегодня, затем остальное; внутри — приоритет, срок, время появления и стабильный ID.
- «Сегодня» определяется по Asia/Yekaterinburg. Очередь не отбрасывает старые нерешённые или будущие заявки. Неизвестная дата появления остаётся неизвестной, не подменяется временем обновления.
- Кнопки «Подробнее», «Назад/Далее», «Обновить / все пункты». Подробности содержат основание и рекомендуемые дальнейшие шаги. Из отчёта можно перейти существующей командой `/report ID`.
- Если источник недоступен/устарел/неполон, виден баннер «Сводка неполная». Ошибка не выдаётся за отсутствие решений. Другие корректные источники продолжают показываться.
- Старый callback не открывает изменившийся/исчезнувший пункт: ссылка привязана к версии содержимого, права проверяются заново.

[Демонстрация на искусственных данных](DECISION_QUEUE_DEMO.md). Запуск без сети: `python tools/decision_demo.py`.

## Источники и связь с кодом

| Источник | Проекция | Что попадает | Что не делается |
|---|---|---|---|
| Консультации | `ConsultationSource` | «Ожидает решения», «Обработка — требуется сверка при сбое» | Нет подтверждения/отказа/Calendar write |
| Проверки | `ReviewSource` из ReportRegistry/MaterialCatalog | Готовые `needs_teacher_review` и `needs_recheck`; scope до payload load | Нет принятия/доработки/баллов/перезаписи immutable результата |
| Отправки | `DispatchSource`, `DispatchLedger.attention()` | `unknown`, `api_rejected`; orphan inflight только с отдельным trusted `review_required=True` | Нет автоматического повтора/сброса state/утверждения доставки |

ConsultationRecord — **нормализованная модель чтения**, не новая схема Google Sheets. Названия/позиции11полей существующего CFG.consultationHeaders не менялись. Реальный Google-export/connector ещё не подключён и должен явно преобразовывать даты в aware datetime без догадок о serial/timezone. Обязателен ConsultationBatch(records, observed_at, complete): исходный timestamp и неполнота сохраняются, не заменяются временем клика. Queue freshness default5минут — технический порог снимка, не правило записи на консультацию. Сетевое обновление snapshots выполняется вне dispatch claim lock; сама подготовка ответа читает только локальные verified snapshots/SQLite.

Текущие внутренние отчёты все требуют преподавателя, поскольку semantic grader/проходной порог пока отсутствуют. Поэтому «Проверки работ» включает такие случаи, а не только содержательные споры. Принятие работы и запись об операторском разрешении сбоя требуют отдельного авторитетного процесса; очередь сама их не изобретает и не имеет кнопки скрытия. Для исчезновения пункта должен измениться его источник. В demo меняется только fake статус консультации. Нельзя закрывать проверку путём перезаписи immutable MaterialCatalog result.

## Доступ и безопасность

Owner ID и sources задаются trusted server configuration. `personal.read` на этого владельца проверяется **до** source callbacks и после сборки; студенты/второй преподаватель не получают private owner queue. Review items дополнительно требуют `student.report` и точного совпадения исходных enrollment/student/discipline/group; права повторно сверяются после чтения источников.

Дубликаты одного source ID с одинаковыми данными объединяются. Конфликтующие копии означают неполный источник, не выбор первой строки. Разные timezone representations одного времени дают одну reference. Никакие raw exceptions, URL/токены и private source payloads в логи/общий ответ не переносятся. Ответ — plain text, disabled previews, ограничение длины и короткие ASCII callbacks≤64bytes.

`TelegramReportAdapter` и `ReportWorker` получают **optional** `decision_service_factory`. Без неё новое направление не активируется; чужие функции/updates не отбрасываются. С factory `/decisions` и `dec:` идут через ту же проверку numeric private sender/current policy и default-off dispatch. Это не включённая команда рабочего GAS-бота и не новый trigger/ежедневная рассылка.

## Проверка

34новых decision tests:13queue +11sources +6menu +4integration. Ещё2регрессионных worker tests воспроизвели ложную блокировку активной соседней попытки: `inflight_or_unknown` теперь остаётся pending/inflight без нового send и без автоматической классификации как orphan. Доказанно unknown/rejected по-прежнему blocked для сверки. Выявленные stale-snapshot/timezone-reference/active-send дефекты сначала воспроизведены тестами.

Итог: **400 Python +101 Node PASS**, `bash tools/check-local.sh` запускает также три offline demos. Реальные Telegram/Sheets/Calendar/почта/оценки/production не использовались. Дальнейшее реальное подключение требует нормализованного консультационного snapshot feed, verified provisioning/runtime и отдельно разрешённой test integration. Автоматических решений и действий этот этап не включает.
