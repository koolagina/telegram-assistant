Дата: 28.10.2026. Исследован только прикреплённый пользователем XLSX. Яндекс Диск и Почта не подключались, токен не использовался. Исходная книга открывалась как ZIP/XML только для чтения, не пересохранялась. В отчёт не включены имена, оценки студентов, содержимое писем или реальные идентификаторы доступа. Книга и её содержимое не копировались в репозиторий/fixtures.

## Риски и расхождения с новым ТЗ

### Старое правило «автомата»

В книге встречается структура формул вида:

```text
SUM(C4:T4)
IF(AA4>56,IF(SUM(AC4:BD4)=4,"автомат","зачет-lite"),"")
```

Это примеры формул структуры, без персональных результатов. Они используют равенство четырём лекционным отметкам. Новое ТЗ требует закрытия **всех фактически состоявшихся обязательных лекций** и строго более 56 практических баллов для очников, а не универсального правила «4 плюса». Нужно независимо установить состав обязательных занятий и происхождение плюсов. Колонку «Волшебство» нельзя считать действующим решением о зачёте; автоматически её не менять и итоговый зачёт не выставлять.

Встречаются также другие пороги (`>25`, `>4.5`, `>4`, `>8`) и разные диапазоны суммирования. Это повод для сверки назначения конкретных листов и формул, а не основание объявить все такие формулы ошибочными: часть может быть шаблоном/служебной логикой или относиться к другому режиму обучения. Тип обучения по имени листа не установлен. Для заочников правило очников автоматически не применять.

Excel SUM обычно пропускает текст, но это не утверждённое предметное правило обработки `*`/пустых клеток. Для отчёта помощника правила конвертации и полноты данных нужно утвердить отдельно.

### Даты могут относиться к прошлому году

В заголовках части листов присутствуют числовые даты Excel 45917 и 45924 с форматом даты. Система дат книги не включает date1904, поэтому это **17.09.2025 и 24.09.2025**. Примеры найдены в C1/I1 XML-частей sheet6, sheet21 и sheet22. Имя файла «26–27» не делает эти даты датами 2026 года.

Пользователь подтвердил 28.10.2026: это актуальный рабочий журнал 2026/27 года. Даты 2025 года остаются выявленным расхождением внутри актуальной книги. Не заменять год автоматически: соответствие конкретной практике и фактической дате требует сверки с расписанием или отдельного подтверждения преподавателя. До такой сверки календарные привязки и историческую посещаемость по этим заголовкам не вычислять.

### Формулы и кеши

Непустой кеш может быть устаревшим; пустой кеш не означает отсутствие работы студента. В OOXML значительная часть формул записана как shared: простой поиск непустого тега f не даёт полного списка выражений для каждой ячейки. Будущий reader должен различать formula / cached_value / cache_missing, разбирать общие формулы либо сохранять явную неопределённость. Не запускать Excel/LibreOffice и не пересохранять книгу ради пересчёта без отдельного решения: пересохранение способно изменить исходные формулы и оформление.

### Не хватает академической идентичности и происхождения

Не установлена утверждённая карта «студент → устойчивая identity → группа → дисциплина → координаты». Порядковый номер строки, фамилия и позиция в листе не годятся как постоянный Student ID. Правила переноса между группами, одинаковых имён, сопоставления Telegram и почты остаются задачей identity/policy.

Лекционный плюс сам по себе не доказывает фактическое присутствие: он мог возникнуть из отработки, бонуса или ручного решения. Без истории нельзя восстановить точный процент физической посещаемости. Неизвестное происхождение помечается как «требует проверки», а не подменяется присутствием.

## Как продолжать локально без токена

1. Создать read-only reader на синтетических XLSX-примерах: связи workbook → worksheets, sharedStrings/inlineStr/numeric, объединения, скрытые поля, системы дат 1900/1904, shared formulas и кеши. Первые тесты должны воспроизвести риск выбора листа по имени, потери заголовка при merged cell и превращения пустого кеша в ноль. Reader не должен содержать функций save/upload/send.
2. Сформировать проверяемую карту блоков и координат по содержимому всех листов. Неоднозначная группа/служебная строка/изменение структуры → review. Проверять, что одинаковая фамилия не связывает автоматически двух людей. Личные данные карты держать только в закрытом локальном хранилище вне Git.
3. Параллельно реализовать локальные Teacher/Student/Enrollment и policy: default deny, только свой `/progress`, предметные права двух преподавателей, отозванный доступ и подмена ID. Пока нет подтверждённого связывания, реальные progress-ответы закрыты.
4. После подтверждения актуальности книги и учебных правил готовить только локальные previews отчётов с датой/версией источника и полнотой. Неизвестные даты, `*`, знаменатели посещаемости и бонусы оставлять явными неопределённостями.
5. Подключение к Диску/Почте и безопасная запись XLSX остаются отдельными этапами. Исследование загруженной копии не подтверждает API записи, актуальность файла на Диске или права доступа к ящику.

## Что проверено в этом проходе

Все 22 worksheet XML-части прочитаны стандартной библиотекой Python; проверены заголовки, формулы/кеши, merges, hidden columns, workbook date system и форматы дат. Формулы не вычислялись, оценки и личности не проверялись. Байтовый SHA-256 книги зафиксирован для проверки неизменности, само значение не включается в публичный отчёт. Внешних запросов, записей, отправок, новых зависимостей и изменений Apps Script нет.

На этапе первоначального структурного аудита reader/identity-модули ещё не реализовывались и старые regression suites не запускались. Следующий локальный этап reader описан ниже. Результаты прежних тестов не являются проверкой Excel-интеграции.


## Read-only reader — следующий локальный этап 28.10.2026

Добавлены `tools/gradebook_read.py` и `tests/test_gradebook_read.py` (16 синтетических тестов). Reader использует только стандартную библиотеку, не имеет сетевых вызовов, записи/пересохранения XLSX, вычислителя формул или функций отправки. Книга выбирается явным локальным путём.

```bash
python tools/gradebook_read.py PATH_TO_LOCAL_XLSX
python -m unittest discover -s tests -p 'test_gradebook_read.py'
```

CLI выдаёт только количество листов/ячеек/формул/пропущенных кешей, координаты заголовков и кандидатов групп, скрытые диапазоны и предупреждения. Имена листов, значения клеток, даты и оценки не печатаются. Python API возвращает raw cells только в памяти: такие объекты могут содержать персональные данные и не должны сохраняться в Git или передаваться напрямую в ChatGPT/Telegram; CLI-проекция отделена. Секреты не нужны.

`Sheet.cell` разрешает опорные merged cells; скрываемые объединением непустые значения вызывают ошибку. Shared formulas сохраняются с указателем на master; выражение дочерней ячейки не объявляется переведённым. Отсутствующий кеш сохраняется как missing, не как 0. Форматы дат учитывают систему 1900/1904; вымышленное 29.02.1900 помечается invalid_date. Проверены archive limits, XML без DTD/entities и запрет внешних/traversal worksheet targets; это ограниченный reader наблюдаемой структуры, не универсальная поддержка всех расширений Excel.

`Sheet.layout` находит только структурные кандидаты в пределах наблюдаемого шаблона: заголовки итогов и А/Т/ДЗ, а также четырёхзначные заголовки групп в A/B. Это не завершённая карта студентов/Enrollment; нераспознанные варианты и дубликаты требуют проверки. Принадлежность строк группе автоматически не назначается, строки не превращаются в student_id, рекомендации не вычисляются. Для форматов других книг потребуется отдельное расширение с тестами.

Повторное чтение загруженной книги подтвердило исходные структурные числа и неизменный SHA-256. Полный локальный Python suite — 80 PASS (16 новых + 64 прежних), текущий Node candidate — 101 PASS. Ни workbook, ни Apps Script snapshots, ни рабочие ресурсы не изменены. Следующий приоритет — identity/Enrollment/default-deny policy и проверенная привязка для `/progress`; реальное раскрытие данных и подключение к внешним ресурсам не выполнялись.
