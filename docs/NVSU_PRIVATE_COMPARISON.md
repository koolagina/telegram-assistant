## Что содержит снимок

Только границы недели, время наблюдения, часовой пояс и по событию — начало/конец, SHA-256 идентификатора/названия/аудитории и флаг защиты. Исходные IDs, названия, аудитории, описания, участники и credential values в журнал не выводятся. Хеши — **не шифрование и не полная анонимизация**: равенство строк и время встреч видны, известные названия можно сопоставить. Снимок остаётся частным; не публиковать журнал в Git/issues. SHA checksum контролирует целостность переноса, а не подлинность отправителя.

GET-only: metadata + не более пяти страниц events (до 200 событий), TLS/no redirects, `singleEvents=true`, явные timeMin/timeMax, строгие dates/timezones/IDs. All-day события сохраняются как занятость с границами суток выбранной зоны. Неполные страницы, дубликаты, invalid dates, API errors или лимиты отвергают весь снимок; до завершения чтения части не выводятся. Повторный page token не игнорируется. Консоль режет результат на части до 3000 символов данных; неполный/смешанный/изменённый набор decoder не принимает.

## Сравнение на стороне разработки

`tools/nvsu_private_snapshot.py` восстанавливает из хешей только уже известные публичные дисциплины/аудитории выбранной недели. Неизвестные события остаются защищёнными; пересечения не трактуются как свободное время. Известная дисциплина с изменившимся временем проверяется существующим `nvsu_sync.plan_sync`, а не новым алгоритмом. Совпадение может дать `bind_existing` как предварительную классификацию; **никакого реального binding/подтверждения ownership не происходит**. Даже `create` означает лишь кандидата плана, а не разрешение записи.

Команда работает только с доверенными приватными локальными файлами, не обращается к Google/Telegram:

```bash
python3 tools/nvsu_private_snapshot.py \
  --source-proof /PRIVATE/PATH/source-proof.json \
  --snapshot-log /PRIVATE/PATH/calendar-chunks.log \
  --date 2026-11-02
```

Source proof — результат существующего `nvsu_source.fetch_week`, с актуальной проверкой даты/учебной недели/преподавателя, не JSON из произвольного сообщения. При получении снимка источник следует проверить заново. Каталоги 0700/файлы 0600, вне Git. Вывод — только агрегаты/числа действий, без частных текстов/IDs/исходных refs. Ledger не создаётся/не меняется, write adapter отсутствует. Всегда `ready_for_apply=false`, `teaching_schedule_verified=false`, `ownership_history_verified=false`, review required. Старый ledger нельзя заменять пустым при реальном подключении.

Снимок не атомарен относительно ручных правок календаря, передан вручную, не удостоверяет владельца и может устареть. Неизвестные события/ранее перенесённые занятия, особенно с изменившимся названием, требуют отдельной проверки. Нельзя превращать агрегаты в исполнимый план, автоматически присваивать ownership/удалять события или включать запись студентов.
