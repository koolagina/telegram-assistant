# Перенос расписания: уточнённые правила 27.10.2026

## Видимое событие Calendar

Переносятся только:

- время начала и окончания занятия;
- название дисциплины;
- аудитория.

Payload локальной модели адаптера содержит `start`, `end`, `title`, `location`: два поля времени представляют один интервал. Нет описания, групп, потоков, типа занятия, ссылок и служебных пометок. Название берётся из поля дисциплины, без префикса «Пр/Лб» и содержимого соседних колонок. Технические связи с источником и Calendar event ID хранятся в отдельном реестре, не в видимом событии.

Строки с одинаковыми временем, дисциплиной и аудиторией объединяются, даже если различаются исходные ID групповых строк. Для дальнейшего сопоставления объединяются внутренние source references, но группы/потоки не переносятся.

## Неделя и конкретная дата

Перед подготовкой синхронизации проверяется конкретная `requested_date`: она должна попадать в выбранную на сайте неделю. CLI требует `--date YYYY-MM-DD`. Возвращённая другая неделя отклоняется даже при сообщении «Расписание отсутствует».

Проверка разметки, преподавателя, заголовков, всех представленных дней, соответствия времени и source date остаётся обязательной. Ошибка HTTP, неполный HTML, неизвестная структура и испорченная дата — ошибки, а не отсутствие занятий. Слепой импорт ICS не используется.

По указанию владелицы сообщение **«Расписание отсутствует» на проверенной странице нужной недели означает, что занятий нет**. Новые события не предлагаются. Для точного обновления план может удалить лишь ранее связанные с импортом события этой недели, если они не были отредактированы вручную. Чужие/ручные события и события другой недели не удаляются. Реального удаления в этом этапе не было.

План имеет явно указанную область — вся выбранная неделя. Дата нужна для проверки правильной недели, это не разрешение импортировать остальные недели ICS.

## Первичное сопоставление и обновление

`tools/nvsu_sync.py` реализует локальную модель плана:

| Ситуация | Действие |
|---|---|
| Единственное точное уже существующее ручное событие | `bind_existing`: связать с источником в отдельном реестре, не менять событие |
| Связанное событие и данные не изменились | `unchanged` |
| Изменились время/дата, дисциплина или аудитория, связь однозначна | `update` того же event ID |
| Исходный ID сменился, но всё содержимое однозначно совпадает | Сохранить тот же event ID, обновить связь |
| Исходный ID и время изменились, а связь нельзя доказать | Сверка, без создания и удаления |
| Нет совпадений или признаков старой ручной записи | `create` с отдельным ключом операции |
| Похожие ручные занятия, пересечение, неоднозначные source refs, пропавшая target-запись | Сверка; план не применяется |
| Пользователь вручную изменил связанное событие | Сверка; автоматическая правка/удаление запрещены |
| Занятие исчезло из полного проверенного расписания | Удаление только неизменённого события, принадлежащего этому импорту |

Для нескольких занятий одного курса с общим ID сначала сопоставляются неизменённые вхождения. Остатки связываются только при единственном соответствии в обе стороны. Индекс строки и изменяемое время не служат единственной постоянной идентичностью. Неоднозначное сопоставление останавливает применение **всего** плана, а не прячется в логах.

Первичное сопоставление частично заполненного календаря требует dry-run: произвольные ручные названия и перенесённое вручную время невозможно надёжно восстановить без связи с источником. Возможные совпадения отправляются на сверку. Точная связь с ручным событием предотвращает дубли, но сама по себе не даёт права его менять/удалять. Для этого требуется отдельное подтверждение владения конкретной записью с проверкой актуального источника и версии Calendar.

## Что реализовано, а что ещё нет

- `tools/nvsu_preview.py`: прежний проверенный parser и offline preview.
- `tools/nvsu_sync.py`: прежний план и алгоритм применения с дополнительными hooks постоянных checkpoints.
- `tools/nvsu_google.py`: Google Calendar v3, readonly default, lazy ADC, стабильные insert IDs, ETag PATCH/DELETE. Поле модели title отображается в summary; время — в start/end dateTime. Служебные связи остаются в локальном ledger.
- `tools/nvsu_state.py`: SQLite ledger/WAL/FULL, target-bound plan, срок 15 минут, источник перепроверяется, операции журналируются до HTTP. Неопределённые результаты доступны для read-only reconciliation; они блокируют последующие планы до сверки.
- `tools/nvsu_source.py` получает выбранную неделю; `tools/nvsu_calendar.py` готовит план, не имеет apply-команды. Fixture/snapshot нельзя применять.
- Ручные точные совпадения сохраняются как protected linked_existing. Передача владения — отдельное явное локальное решение с live proof/ETag, не автоматическое следствие совпадения.

Реальная Google-интеграция и права не проверены, Python не подключён к Apps Script. Ни один настоящий event не читался/не изменялся в этапе подключения. ETag защищает версию отдельного события; между проверкой конфликтов и create остаётся окно конкурентной записи сторонним клиентом. Приёмка нужна на отдельной sandbox. Предварительный план, команды и ограничения: [NVSU_CONNECTION_PLAN.md](NVSU_CONNECTION_PLAN.md).

## Команда для плана

```sh
python tools/nvsu_preview.py \
  --html PATH_TO_VERIFIED_HTML \
  --lecturer-id ID --teacher-name NAME --date YYYY-MM-DD \
  --existing PATH_TO_TEST_EVENTS_JSON \
  --bindings PATH_TO_TEST_BINDINGS_JSON \
  --sync-plan --output /tmp/nvsu-plan.json
```

Оба файла `--existing` и `--bindings` обязательны для режима `--sync-plan`; отсутствие файлов не считается пустым календарём или пустой историей. Все файлы — локальные, без секретов. Начальный пустой bindings допускается только как явное известное состояние, после просмотра существующих ручных занятий.

## Проверки

`python -m unittest discover -s tests -p 'test_nvsu*.py'` — **64 PASS**: 8 parser/preview, 24 sync-model, 24 Google/state и 8 source/CLI. Включены объединение разных source IDs, отсутствие групп/служебных полей в adapter payload, update того же ID при изменении трёх параметров и переносе дня, повторный импорт, empty-week, чужие/ручные события, смена source ID, после-preview изменение Calendar, accepted-create timeout и CLI без обязательных файлов.

Это локальные проверки на очищенных реальных HTML-структурах и искусственном Calendar. Работа реального Google Calendar/Apps Script и права не проверены. Производственный бот и все `.gs` snapshots не изменялись в этом уточнении.
