## Почему нельзя слепо импортировать ICS

Все три ICS вернулись с HTTP 200 и `text/calendar`, но:

| Выбранная дата | VEVENT в экспорте | Фактические даты |
|---|---:|---|
| 19.10.2026 | 82 | 19–23 октября и последующие недели ноября |
| 26.10.2026 | 62 | 2–19 ноября, хотя HTML текущей недели сообщает отсутствие расписания |
| 02.11.2026 | 71 | 2 ноября – 1 декабря |

В этих файлах нет UID, timestamps — floating local (`DTSTART:20261102T…`), а многогрупповые занятия повторены отдельными VEVENT. Экспорт не ограничен выбранной неделей. Поэтому эти файлы не загружаются в Calendar и не используются как доказательство покрытия выбранной недели. Отдельно требуется исследование контракта всего экспорта, если он понадобится позже.

## Реализованный read-only parser/preview

`tools/nvsu_preview.py` использует только стандартную библиотеку Python. Он читает **локальный HTML**, не содержит сетевого клиента Google и не имеет операции записи в Calendar.

Подтверждённая структура:

- один `table#timetable`;
- дневные заголовки и покрытие понедельника–субботы в выбранной неделе;
- заголовки колонок «время, п/г, дисциплина, группы, поток, кабинет», либо явное «занятий нет» для пустого дня;
- строка из семи ячеек, `td.time`, публичная ссылка `setlink/<ID>?date=YYYY-MM-DD&time=HH:MM:SS`, предмет, группы, кабинет;
- проверка совпадения даты строки с дневным заголовком, времени ячейки с URL, положительной длительности и попадания в выбранную неделю;
- никакого пропуска испорченной строки ради частичного «успешного» расписания.

HTML без таблицы принимается только при явном сообщении «Расписание отсутствует» и проверенном evidence выбранной недели/преподавателя. Состояние возвращается как `source_reports_no_schedule`: по указанию владелицы это отсутствие занятий выбранной недели, без добавления событий. Остальные события календаря всё равно учитываются при подборе консультаций.

Preview сравнения с существующими событиями:

- точное единственное совпадение времени, названия и места → `already_present`;
- любое неоднозначное пересечение, включая ручное событие с другим названием → `review_overlap`, без создания/перезаписи/удаления;
- нет пересечения → `create_candidate`, только кандидат на будущее создание, никакой записи;
- некорректный интервал или отсутствие timezone в существующем Calendar JSON → отказ, а не предположение о свободном времени.

На **искусственном** частичном календаре с одним совпадающим занятием для следующей недели preview дал: 1 `already_present`, 10 `create_candidate`, 0 `review_overlap`. Рабочий календарь для этого не читался. Ручные записи не изменялись.

CLI:

```sh
python tools/nvsu_preview.py --html PATH_TO_HTML --lecturer-id ID --teacher-name NAME --date YYYY-MM-DD
# Для read-only сравнения: --existing PATH_TO_TEST_CALENDAR_JSON
# Для локального результата: --output /tmp/nvsu-preview.json
```

Если `--existing` отсутствует, результат явно помечается `not_compared_calendar_export_required`. Отсутствие выгрузки не трактуется как пустой календарь.

## Тесты, fixtures и ограничения

`python -m unittest discover -s tests -p 'test_nvsu_preview.py'` — 8 PASS. Проверены предыдущая/текущая/следующая недели, explicit no-schedule, неизвестная разметка, неверный преподаватель/неделя, испорченные дата/время, многогрупповая строка, однозначное совпадение, пересечение и детерминированность preview.

Fixtures — очищенные фрагменты реально полученной структуры; имена/subject labels/внешние ссылки материалов и ряд ID заменены тестовыми. Они не выдаются за оригинальные неизменённые HTML. `tests/fixtures/nvsu/provenance.json` хранит SHA исходных ответов и очищенных файлов. Неочищенные HTML/ICS оставлены вне репозитория в `/tmp`; приватные ссылки материалов в fixtures не сохраняются. Исходный parser также локально выполнен на трёх полных HTTP-ответах до очистки.

Эта утилита ещё **не подключена к Apps Script кандидату**. Реального импортера с записью/ledger нет. Следующие шаги: адаптер подтверждённых данных и диапазона/свежести, dry-run против отдельного тестового Google Calendar, сохранение стабильных source keys, повторный импорт без дублей, работа с изменившимися парами и только после проверки включение источника для консультаций. Календарь заполнен частично, поэтому флаг полной занятости остаётся выключенным. Production не менялся.
