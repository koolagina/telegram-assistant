# Учебная сводка: журнал и проверки работ

30.10.2026. **Завершён локальный блок; не развёрнут.** Пользователь без компьютера, действий от него сейчас не требуется.

## Реализация

`tools/academic_overview.py`: `AcademicOverview.read` объединяет существующие `ProgressReader` и `ReportReader`, сохраняя две отдельные секции. Журнал показывает буквальные записи; проверки работ остаются предварительными результатами, требующими преподавателя. Нет расчёта долгов, суммы баллов, зачёта, автоматического принятия работы или записи в журнал.

`ProgressReader.authorize_enrollment` повторно проверяет точный mapping без чтения XLSX. `ReportReader.list_enrollment` выбирает только отчёты того же enrollment, проверяет совпадение student/discipline/group с авторизованным журналом, сортирует по report ID и читает до пяти payload на страницу. Перед чтением проверяется вся связка enrollment; после чтения — права на выбранные работы. После второго источника повторно проверяются права journal-view. Ошибка источника/связи/права блокирует сводку целиком; частичный ответ не возвращается. Отсутствие сохранённых проверок не означает отсутствие задолженности.

Это согласованная локальная композиция, **не распределённая транзакция** между XLSX и хранилищем отчётов. Общий runtime должен подавать текущую policy и согласованные версии источников. Политика может измениться после возврата: при реальной отправке нужно заново подготовить ответ, не отправлять сохранённый текст как авторизованный артефакт. Наличие Python Context не подтверждает аутентификацию.

`prepare_overview_reply` готовит plain text до 3500 UTF-16 единиц, очищает управляющие символы, отключает link preview, не использует parse_mode. Сводка ссылается на существующие команды деталей `/progress REPORT` и `/report REPORT`.

Локальные команды-кандидаты:

- `/overview ENROLLMENT` — студенту только собственное действующее обучение;
- `/student ENROLLMENT` — преподавателю по академическим правам;
- необязательное `page N` — следующая страница проверок.

Это технические ID, не ФИО и не разрешения. Удобный выбор дисциплины/студента по подтверждённому реестру остаётся следующим UI-этапом. Существующий `/progress` не переопределён.

`TelegramReportAdapter` получил необязательный `overview_factory`, по умолчанию `None`. Только доверенный verified-poll provider и точная фабрика AcademicOverview допускают подготовку нового ответа. Проверки sender/private chat сохраняются; group chat не читает данные. Нет webhook, новой отправки, poller, production конфигурации или подключения к работающему Apps Script.

## Приёмка

24 новых теста: 17 в `tests/test_academic_overview.py`, 7 в `tests/test_overview_telegram.py`. Тесты написаны до соответствующих реализаций: сначала воспроизведены отсутствие модуля и неподдерживаемый параметр адаптера; затем проверены позитивные и отрицательные сценарии.

Проверены обе секции, student/teacher projection, чужой студент/преподаватель, несовпадающая identity реестров, чужой enrollment без загрузки его payload, отзыв при загрузке отчёта, устаревший журнал, повреждённый результат, пустой список без вывода об отсутствии долгов, постраничность и границы, безопасный plain text, одинаковые отказы, default-off, личный/group chat и сохранение старого `/progress`.
