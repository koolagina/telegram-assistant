# Журнал → личный прогресс: локальный блок 30.10.2026

Статус: **локальный компонент, не подключён к рабочему боту**. Реальный журнал не читался и не изменялся в этом блоке. Пользователь вне компьютера; его действий сейчас не требуется.

## Что готово

`tools/academic_progress.py` соединяет существующие `gradebook_read.Workbook` и `assistant_access.AccessPolicy`. `ProgressReader.read` возвращает только явно сопоставленные ячейки одного enrollment. `JournalMap` задаётся доверенным реестром: enrollment/student/discipline/group, SHA-256 файла, индекс листа, строка и разрешённые `JournalField`. Нет поиска по похожему ФИО, угадывания группы из заголовка или переноса привязки на обновлённый файл.

Проверки прав выполняются до загрузки и повторно перед возвратом. Студент получает только собственный действующий enrollment; преподаватель — по действующим правам, владелец с явным академическим grant — также исторические записи. ChatGPT требует соответствующего scope; email допускает только авторизованное чтение, без отправки. Эти контексты должен создавать будущий аутентифицированный транспорт: Python-объект сам по себе не подтверждает личность. MAX не подключён.

Выход содержит идентификатор учебного пункта, его вид и записанное значение. Не содержит ФИО, названия листа, координат, формул или соседних строк. Значения Decimal передаются строками без потери точности. Пусто → `not_recorded`, формула даже с кешем → `formula_unverified`, ошибка ячейки → `source_error`. Итоги можно читать только из явно выбранной literal-ячейки; расчёт итогов, трактовка отметок посещаемости, зачёт/незачёт и запись баллов отсутствуют. Объединённые ячейки отклоняются, чтобы не прочитать другую строку.

Изменение SHA файла требует пересмотра mapping. Это намеренная остановка: автоматическое обновление учебных материалов работает отдельно, а перенос строки студента требует подтверждённой идентичности. SHA связывает mapping с байтами, но не доказывает происхождение и свежесть. `live_verified=false`, `credit_written=false` всегда. Ответ — снимок локального файла, не актуальность облачного журнала.

## Проверка

20 новых тестов в `tests/test_academic_progress.py`: сначала отсутствующий компонент дал ожидаемый ImportError; после реализации пройдены права, чужие/неизвестные записи с одинаковым отказом, отказ до чтения, отзыв во время загрузки, повторное использование enrollment, ChatGPT scopes, email без отправки, историческое чтение владельцем, формулы/ошибки/пустые ячейки, пересечения mapping, merged cells, безопасные ошибки, независимые результаты. Сквозной тест создаёт искусственный XLSX и использует настоящий `read_workbook`: студент и преподаватель получают literal, кеш формулы скрыт, изменённый файл отклонён. При этой проверке исправлено соответствие индекса листа существующему parser (индексация с 1).

Команды: `python3 -m unittest discover -s tests -p test_academic_progress.py`; `bash tools/check-local.sh`. Полный набор: 649 Python +448 Node PASS, 9 offline демонстраций; лог /tmp/kulagina-academic-progress-check.txt.

## Что осталось для подключения

1. Подтверждённый реестр идентичностей и enrollment, проверенное сопоставление строк/столбцов актуального журнала. Никакого автоматического сопоставления ФИО.
2. Ограниченный read-only источник актуальной копии с provenance/датой; обновление mapping после изменения файла.
3. Согласование значений отметок и правил суммирования. Сейчас значения выдаются буквально, без академических выводов.
4. Связать этот отдельный journal-view с существующим `/progress` результатов проверки работ и teacher-report маршрутом, сохранив разные типы данных и права. Нынешний Telegram `/progress` не изменён.
5. Аутентифицированные Telegram/ChatGPT адаптеры и отдельное разрешение перед реальными чтениями/отправками; подтверждённая почта и отправка — отдельный этап.
